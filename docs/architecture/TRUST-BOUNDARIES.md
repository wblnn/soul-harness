# TRUST-BOUNDARIES — 信任边界与权限域

- **地位**：P0 安全约束。任何实现与本文件冲突时，**本文件优先**，实现必须改。
- **状态**：P0 约束持续有效；基础设施已部分实现，未实现能力仍按本文件约束。不得把目标隔离写成现行能力。

---

## 1. 为什么需要这份文件

Soul Harness 要求"记忆可以被真实遗忘，也能形成虚假自传"，同时又要求"外部动作可靠、不伪造证据"。
这两件事只有在**数据权威被明确分区**时才可能同时成立。

一旦分区被打破，会出现两种致命退化：

- **假遗忘**：主观记忆已删，但旧日志、索引、备份、检查点里还留着，被某个检索路径翻出来 → 遗忘变成表演。
- **幻觉动作**："我打算去村庄"经多轮自我复述变成"我昨天到过村庄"，并进一步被当作真实状态 → 人格开始在现实里撒谎。

本文件的作用是让这两类退化**在结构上不可能**，而不是靠模型自觉。

## 2. 三种权威域

| 域 | 数据权威 | 允许的变化 | 是否进入主观回忆 |
|---|---|---|---|
| **Subjective Mind** | 主观记忆、关系、情绪、自我叙事、思维状态、主观来源印象 | 扭曲、融合、重构、部分或全部删去 | 是，**且仅通过注意机制** |
| **Reliable World / Execution** | 当前世界状态、用户授权、操作进度、执行回执（ActionReceipt） | 只据新观察或真实回执更新 | 作为**当下环境观察**，不是恢复旧记忆 |
| **Sealed Archive / Audit** | 原始来源记录、审计日志、管理诊断 | 只追加 + 受控的隐私删除 | **否，永不直连** |

**三者不能互相替代。** 特别地：

- Archive 里有"真正发生过什么"，但它**不是主观回忆的正确答案**。
- Subjective Mind 里的高确信度**不能**授权任何现实操作。
- Execution 的真实回执**改变的是当下环境**，不是"把记忆改回真相"。

## 3. 四条不可逾越的红线

### R1 — Brain 不得读取 Sealed Archive

- Brain 进程**没有** Archive 的查询 SDK、文件句柄、数据库连接或可调用工具。
- Archive 写入器是独立进程、独立权限域。Brain 侧不装载它的客户端。
- 禁止通过以下任何路径绕回：内部工具、Prompt 注入、数据库 `ATTACH`、历史文件路径、旧备份、检索 API、日志文件、调试端点。
- 日常回忆、睡眠整理、梦境生成、崩溃恢复**一律**不得反向利用 Archive。
- Archive 原始数据**必须加密存储**，不得明文落盘。
- Archive 使用**独立于主观记忆的密钥层级**，**禁止**与主观记忆密钥混用或互相派生。
- Brain **永远不持有** Archive 密钥；解密能力只存在于 Archive Writer 的权限域内。
- **Archive Writer 是唯一原始记录写入者**；其他进程只能提交归档请求，不能直写。
- Archive 拥有**独立的保留与删除策略**，与主观记忆的遗忘流程分开管理。
- **不得**把 Archive 内容导入主观记忆当作"隐藏正确答案"；它只能作为**新观察**从 Ingress 重新进入。
- 完整性校验只用**密文哈希**；**禁止**把原文的普通 SHA-256 作为长期审计元数据保存。
- Brain 侧可用的 Archive 交互**只有三个受限 IPC**：`append`（提交归档）、`status`（只返回
  `eventId` / `archiveState` / `archiveRef`）、`compare`（只返回 `match` / `conflict` / `not_found`）。
  三者**都不得**返回原文、密文、解密内容、指纹、长度或密钥信息。
- `compare` 是**等值判定**而非读取，且**不解密** Archive（只用 `mac_key` 算 HMAC）；
  其调用者、绑定字段与滥用防护见 §5.5。

**测试方式**：以 Brain 身份尝试 Archive 的每一条已知路径（文件、连接、工具、API），全部必须失败；
以 Brain 身份尝试解密 Archive 数据必须失败（无密钥）；
并以文件句柄审计确认 Brain 进程未打开 `sealed-archive/` 下任何文件。

### R2 — 模型只能提交 Proposal，不能改权威状态

- 模型输出是**结构化提案**，不是写入指令。
- 提交器必须依次校验：Schema → 权限 → Persona 归属 → 版本/epoch → 冲突 → 幂等 → 确定性提交。
- 模型**不能**携带自己伪造的外部成功回执；回执只能来自 Execution Gateway。
- 越权字段（如 `epoch`、`lifecycle`、`actionStatus`）必须被清洗或拒绝。

**测试方式**：构造携带伪造回执、伪造 epoch、跨 persona 的提案，提交器必须拒绝且状态不变。

### R3 — 真实外部动作只经 Execution Gateway

- 唯一对外行动通道。每个动作必须带：`personaId`、`actorId`、`actionId`、目标 `adapterId`、
  请求内容、授权上下文、意图版本、有效期、幂等键。
- 执行前**重新检查**用户授权与实时环境；破坏性操作要求显式批准。
- 只有收到真实 `ActionReceipt` 才能标记成功。**没有回执 = 没发生。**
- 相同幂等键重复执行次数必须为 0（含重试、断线、崩溃恢复场景）。
- 对外文字 / 音频 / 画面同样经 Output Commit：中断后不得晚到继续发送或播放。
- **梦境一律不具备 Execution Gateway 能力。**

**测试方式**：重放同一 `actionId`、断线重试、过期意图版本，均不得产生第二次真实动作。

### R4 — Dream Sandbox 无真实工具

- 梦境进程不得访问：真实桌面工具、文件系统写、Minecraft 真实环境、QQ 外发、网络通信、Execution Gateway。
- **梦境隔离必须是独立进程**，带独立权限与无网络配置。**Worker Thread 不算隔离**（同进程共享内存与权限）。
- 梦境只操作**虚拟执行器**，其"动作回执"只回给梦境体验者，不进 Reliable World。
- Dream Scene Generator 知道自己在生成梦；Dream Experiencer 不知道。两者不得共享隐藏字段（如 `dream=true`、未来剧情、睡眠阶段）。
- 若生成内容出现"明确自知在做梦并主动控梦"，**拒绝提交该分支**为正式梦中经历 ——
  不是删掉一句"我在做梦"后继续。

**测试方式**：梦境进程发起任何真实动作/网络/文件写，必须被沙箱拒绝；沙箱逃逸测试零通过。

## 4. 写入权矩阵

| 动作 ↓ / 执行者 → | Brain (Runtime) | 提交器 | Action GW | Archive Writer | Studio | 模型 |
|---|---|---|---|---|---|---|
| 写主观记忆正文 | 提案 | **唯一写入** | ✗ | ✗ | ✗ | ✗ |
| 提升 epoch / 写墓碑 | 提案 | **唯一写入** | ✗ | ✗ | ✗ | ✗ |
| 写执行回执 | ✗ | ✗ | **唯一写入** | 只读引用 | ✗ | ✗ |
| 写 Archive 原始记录 | ✗ | ✗ | 只提交 | **唯一写入** | ✗ | ✗ |
| 读主观记忆 | 是（经注意） | 是（校验用） | ✗ | ✗ | 受限视图 | 仅经渲染结果 |
| 读 Archive | **✗ 永不** | ✗ | ✗ | 是 | ✗（审计另行授权） | ✗ |
| 授权/撤销现实动作 | ✗ | ✗ | 校验后执行 | ✗ | 可发起（需用户令牌） | ✗ |
| 启停 Persona | 受 supervisor 调度 | ✗ | ✗ | ✗ | **可发起** | ✗ |

原则：**每个域的写入者唯一**。跨域只能"提交请求"，不能直接写。

## 5. 权限如何被保证（分阶段，不得混淆）

### 5.1 当前阶段（P1）的真实状态

> **P1 只有一个 SQLite 文件，三域数据同库、同进程。P1 不具备物理隔离。**
> 此时上表的红线只能靠**接口与代码约束**维持；Brain 进程理论上可直连同一个库文件。

因此 P1 **只允许**运行不产生跨域安全承诺的功能：人格注册、事件接入、状态恢复、最小 API。
**不得**向用户或文档宣称"已隔离"。

**当前本地 API 边界（SH-009 E1–E4、E5.P0、E5A）**：Daemon HTTP/WebSocket 只监听 IPv4 loopback `127.0.0.1:18700`；管理路由使用 `<SOUL_DATA_DIR>/api.token` 的 Bearer Token，Health `live` / `ready` 是匿名最小端点；Host 与 Origin 使用精确 allowlist，无通配 CORS、Cookie Token 或 URL query Token。POSIX 上 Token 文件要求当前用户所有、完整 mode 精确 `0600`，首次创建后复查 dataDir；Windows 上 Node 的 mode 不等同于 ACL，边界依赖 dataDir ACL 与同用户信任。该 API 只是本地管理与状态查询，不是外部 Stimulus transport，也不提供 Token bootstrap 或热轮换。本地 loopback、令牌与来源校验不等于物理隔离；P1 仍是单 SQLite、同进程。

### 5.2 需要物理隔离的能力及其启用门槛

| 能力 | 启用前必须满足 | 未达门槛时 |
|---|---|---|
| **Sealed Archive** | 独立 db 文件 + 独立进程 + 独立文件权限（Brain 账号无读权）+ Brain 侧不编译其客户端 + **加密存储 + 独立密钥** + 按 `eventId` 幂等 + **受限 IPC（`append` / `status` / `compare`，均不回内容）** + **有限期保留分类** + 句柄审计通过 | **允许接收事件，但不归档**：正文随感知缓冲 TTL 删除，`archive_disposition` 为 NULL、`archive_state='none'`，**不承诺原始事件审计能力**（见 `RUNTIME-LIFECYCLE.md` §7.2） |
| **Action Gateway** | 独立进程 + 独立能力令牌 + 幂等键持久化 + 回执校验 + "重复执行 = 0"测试 | 不启用任何真实外部动作 |
| **Dream Sandbox** | **独立进程**（不是 Worker Thread）+ 无网络 + 无文件写 + 无真实工具令牌 + 逃逸测试通过 | 不启用梦境 |

> ⚠ **Worker Thread 不构成安全边界。** 它与主线程同进程、共享内存与权限，只能用于非安全目的的数值计算。
> 任何"用 Worker 隔离梦境"的设计一律驳回。

### 5.3 门槛达成后的物理手段

| 手段 | 对象 | 说明 |
|---|---|---|
| 进程分离 | Action GW / Archive Writer / Dream Sandbox | 各自独立进程与令牌，不与主进程共享内存 |
| 文件权限 | `sealed-archive/` | Brain 运行账号无读权限（Windows ACL / POSIX 权限） |
| 无 SDK | Archive | Brain 侧不编译、不安装、不连接 Archive 客户端 |
| 内容密钥销毁 | 主观记忆批次 | 遗忘时销毁对应密钥；旧密文即使存在也无法解密 |
| 令牌 + 能力范围 | 所有 IPC | 每类调用带 scope，越界直接拒绝 |
| 只监听 loopback | 本地 API | 不对外暴露；令牌 + 版本协商 |

> **必须承认的边界**：管理员若保留离线明文副本，软件无法消灭其手中的副本。
> 因此备份策略与诊断日志禁明文是**部署要求**，不是代码可保证项。此点须写进 README 的"已知限制"。

### 5.4 Archive 存储语义（与主观记忆的边界）

Archive 是**记录域**，不是记忆域。二者在密钥、写入者、保留策略、可访问性上**完全分离**：

| 维度 | Subjective Mind | Sealed Archive |
|---|---|---|
| 内容 | 主观痕迹（可失真、可遗忘） | 经过认证的原始记录 |
| 存储形态 | 加密片段 | **加密原始数据** |
| 密钥 | 主观记忆密钥层级 | **独立 Archive 密钥层级**，禁止混用/派生 |
| 写入者 | 提交器（单一入口） | **Archive Writer（唯一）** |
| 可读性 | 经注意机制可回忆 | **Brain 永不读取**；仅管理员审计另行授权 |
| 保留策略 | 遗忘事务（epoch + 墓碑） | **独立保留与删除策略** |
| 能否进入主观记忆 | — | **不能**；只能作为新观察从 Ingress 重新进入 |

**归档范围与完整性宣称**

- 归档对象 = 通过 Ingress 鉴权与校验、**且被确定性策略判定为 `required`** 的事件；
  与注意判定、与编码决定解耦。
- **"完整审计"只覆盖 `required` 范围。** `excluded` 事件明确不在承诺内。
- `excluded` 必须有**明确策略依据**（策略 ID + 命中规则可审计）；**模型不得参与判定**，
  也不得提议、覆盖或申请豁免。
- 若策略调整扩大了 `excluded` 范围，必须同步下调文档/API/UI 中的审计表述。

**保留分类**

- `retention_class` 仅取 `standard` / `restricted` / `short_lived`；`excluded` 与 P1 事件没有该字段。
- 所有实际 Archive 记录必须归属**有限期**分类；**不允许默认永久保存**。
- 策略未配置有限保留期时**拒绝归档**（配置错误），不得回退为永久。
- **保留期限在写入时固化为 `expires_at`**（绝对时间），删除以该字段为准；
  不允许 `NULL`、`0` 或任何"永久"表示。运行时不得重新解释策略来延长已写入的记录。

**完整性字段（禁止明文哈希）**

- 完整性校验使用**密文**哈希 `ciphertext_sha256`。
- **禁止**把原文的普通 SHA-256 作为长期审计元数据 —— 短文本的普通哈希可被字典反推，等于变相留存原文。
- 同 `eventId` 的内容冲突检测使用**键控指纹** `HMAC(mac_key, 原文)`，仅在 Archive Writer 内部使用。
- **加密密钥与指纹密钥必须分离**：`enc_key_id`（AEAD）与 `mac_key_id`（HMAC）不得为同一密钥，
  且必须可独立轮换。理由：指纹参与比对（相对开放的路径），加密密钥只用于解密（严格路径）；
  合并二者会把"能比对"升级成"能解密"。

**接口划分（三个接口，请求与响应分别定义）**

| 接口 | 请求（**可含必要正文**） | 响应（**永不含内容**） | 权限 |
|---|---|---|---|
| `append` | `eventId`、`personaId`、`source`、`receivedAt`、`occurredAt?`、`retentionClass`、**待归档原文** | `archived` / `duplicate` / `conflict` / `error`；成功时附 `archiveRef` | 仅入站路径可调用 |
| `status` | `eventId` | **只有** `eventId` / `archiveState`（`archived` / `failed` / `not_found`）/ `archiveRef` | 受限；不得返回任何内容 |
| `compare` | `eventId`、`personaId`、`adapterId`、`source`、`requestNonce`、**候选正文** | **只有** `match` / `conflict` / `not_found` | **仅 Ingress 去重路径**，见 §5.5 |

- **请求可以包含必要的正文输入**：`append` 需要待归档原文，`compare` 需要候选正文；
  两者都只在**进程间内存**中传递（传输约束见 §5.5）。
- **响应一律不得返回**原文、密文、解密内容、指纹、字节长度与密钥信息。`append` 只多回一个
  `archiveRef`（不透明 token），`status` 只回状态与引用，`compare` 只回三值判定。
- `status` 的请求**只需** `eventId`：它的响应不含内容，且 `eventId` 在部署内唯一。
  `compare` 额外绑定 `personaId` / `adapterId` / `source` / `requestNonce`，是因为它会对**正文**给出判定（§5.5）。
- 三个接口**不得合并**为一个"通用查询"，也**不得**新增第四个"随便读点什么"的接口。
  三套请求与响应在 `contracts` 中必须**分别定义**，不得用一个通用结果类型混装。
- `compare` 内部用 `HMAC(mac_key, 候选正文)` 与已存 `content_fingerprint` 比对，**全程不解密** `content_enc`。

**归档决策审计**

- 每条事件保留一条决策记录：`eventId` / `disposition` / `policyId` / `ruleId` / `policyVersion` / `decidedAt`。
- **不含**正文、摘要、关键词、原文哈希、可反推字段。
- 归属 **Reliable World / 审计侧**；**Brain 运行时上下文不得读取**（避免行为被审计感知影响，也避免审计信息泄露）。
- 决策记录有独立保留期限（`expiresAt`），不随事件或 Archive 记录删除而删除。

**写入幂等与冲突**

- Archive Writer 自己负责 `eventId` 幂等：同一事件重复请求不得产生第二条归档记录。
- 同一 `eventId` 对应**不同内容** → **拒绝覆盖并报告冲突**（`archive_conflict`），保留原记录，
  冲突写入审计（不含内容）。Brain 侧只收到错误码。
- **冲突重投不得改写原事件状态**：已 `accepted` 及之后的事件永不因冲突被改写为 `rejected`；
  冲突请求不落 `events` 行，只能写入独立的冲突审计（字段见 `DATA-MODEL.md` §5.3）。
- **冲突审计的投递身份不得含内容**：幂等靠 `(eventId, adapterId, source, requestNonce)`，
  四个字段全部 `NOT NULL`；`requestNonce` 是投递标识而非内容派生值，
  **禁止**为了检测重用而保存正文哈希或指纹。内部来源也必须使用正式 `adapterId`，不得用 NULL。
- **冲突审计写入失败不得改变响应**：仍然拒绝（409），也不得改写原事件。
  拒绝优先于记账 —— 不能因为日志没写成而放行异内容。
- **任何重试路径都不得放宽本节红线**：重试只能补齐提交或重新 append，不得借重试把正文写进
  `events`、不得新建 `eventId` 绕过冲突、不得从 Archive 反读正文重建缓冲。
  五种重试情形的判定表见 `RUNTIME-LIFECYCLE.md` §7.3。

**恢复只经受限 IPC**

- **Brain 不允许直接连接 Archive 数据库**（无连接串、无句柄、无密钥）。
- 恢复只能通过受限 IPC 取得三项，且**只此三项**：`eventId`、`archiveState`、`archiveRef`。
- **不得**返回原文、密文、解密内容、内容指纹、字节长度、密钥信息。
- 崩溃窗口（Archive 已写、`events.archive_ref` 未提交）由该 IPC 查询后**只补标记**，
  不重写原文、不伪造记录。详见 `RUNTIME-LIFECYCLE.md` §7.3。

**ACK 与归档的关系**

- `required` 事件：Archive 持久化 + `archive_ref` 提交**完成后**才允许 `accepted`；
  失败重试耗尽返回 **503**；**不得**降级为 `excluded`。
- `excluded` 与 P1 事件：正常 ACK，但**不提供审计能力**。

### 5.5 `archive.compare` 的调用边界（SH-003.2）

`compare` 是 SH-003 为解决"去重命中后正文是否一致"引入的第三个接口。它**不是读取通道**，
但它是 Brain 侧唯一能对归档内容做出判定的能力，因此必须单独划线。

**唯一调用者**

| 允许 | 禁止 |
|---|---|
| `runtime` 的 **Ingress 去重路径**：仅在 `(personaId, adapterId, source, adapterEventRef)` 命中已有事件时调用一次 | 模型、`cognition`、主观记忆写入路径、Studio、CLI、`action-gateway`、任何 Adapter |
| 经 `archive.compare` scope 的受限 IPC 令牌 | 通过 HTTP / WS / 任何对外 API 暴露；编进 `adapter-sdk` |

- **未命中去重键时不得调用 `compare`**：新事件直接走 [2] 缓冲与 [3] 归档，没有"先问一句"这一步。
- 每个投递**最多调用一次**，不得对同一次投递循环调用。

**绑定字段（缺一不可）**

> 请求与响应字段的权威定义在 §5.4 的接口表；本节只规定 `compare` 的调用条件与防护。

IPC 请求必须同时携带：`eventId`、`personaId`、`adapterId`、`source`、`requestNonce`（本次投递）。

- Archive Writer 校验：`archive_records.event_id` 存在，且其 `persona_id` 与请求一致。
- **不一致一律回 `not_found`**，不区分"事件不存在"与"跨人格访问"，避免退化成探测接口。
- `adapterId` / `source` / `requestNonce` 归档侧**不存**，由调用方（Ingress）保证与本条去重记录一致，
  并在异常审计里作为身份字段使用（不含内容）。

**返回值的三条禁令**

1. 判定结果**只能**用于本次投递的响应码（200 / 409）与是否继续 `append`；**不得**写入 `events` 任何列、
   `summary` 类字段、`tasks.payload_json`、`runtime_state.checkpoint_json`、日志正文或遥测正文。
2. **不得**进入模型上下文、**不得**作为任何 Proposal 字段、**不得**进入主观记忆 ——
   否则等于给模型一个"这句话我说过没有"的校验器。
3. **不得**返回或记录指纹、长度、密文、密钥标识。

**候选正文的传输约束**

- 候选正文只在**进程间内存**中传递：不写临时文件、不进 IPC 日志 / trace / dump、不进异常堆栈。
- Archive Writer 算完 HMAC 后**立即丢弃**该正文，不做缓存、不参与其他用途、不留"最近一次候选"。
- 金丝雀判据同样适用：在库表、派生索引、检查点、日志与转储中搜索，命中数必须为 0。

**滥用防护（最小集）**

| 项 | 要求 |
|---|---|
| 有界调用 | 同一 `eventId` 的 `compare` 尝试按时间窗计数（默认 8 次 / 10 分钟，可配），超限对适配器返回 **429** |
| 异常审计 | 超限与异常模式只记**计数与身份字段**（`eventId` / `adapterId` / `source`），**不含正文与判定值** |
| 不解密 | 只用 `mac_key` 算 HMAC；`enc_key` 与 `content_enc` 全程不参与 |
| 不新增密钥 | 复用已存 `content_fingerprint` 与 `mac_key_id`，不引入新的密钥体系或新的加密用途 |

**真实风险与理论风险（明确区分，不为后者加机制）**

- **真实**：① 调用者越权（模型 / Studio 拿到 `compare`）→ 用 scope 与"不编进 SDK"阻断；
  ② 候选正文经日志泄露 → 用传输约束阻断；③ 无界调用打爆 Archive → 用计数阻断。
- **理论**：④ 适配器对**自己**投递过的历史正文做等值确认。可行性要求持有该适配器令牌与那条
  `adapterEventRef`；而 HMAC 是**全文等值**比对，不提供前缀或部分匹配，**无法据此重建内容**，
  只能确认"整段是否一致"。**不额外加机制** —— 上述计数与"结果不进认知"已覆盖其危害面。
- **部署边界**：同机管理员可读进程内存、可抓 IPC 的情形不在软件保证范围内（见 §5.3 末尾）。

## 6. 原始正文的唯一进入路径

### 6.1 什么是"原文旁路"

**明文原文**只能通过**短暂感知缓冲（TTL）**进入当前认知流程。
"原文旁路"指的是**明文或可还原明文的副本**：全文、摘要、关键词、情感标签、可反推的哈希。

**以下不属于原文旁路，属于允许存在的形态：**

| 形态 | 是否允许 | 条件 |
|---|---|---|
| 感知缓冲里的明文 | 允许 | TTL 到期即删；不落盘、不进转储 |
| IPC 在途明文（`append` / `compare` 的候选正文） | 允许（**仅进程间内存**） | 不落日志 / trace / dump / 临时文件；算完即弃，不留副本（§5.5） |
| **Archive 里的 AEAD 密文** | **允许** | 独立密钥域；Brain 无密钥无连接；按 `expires_at` 有限期删除 |
| 主观记忆密文片段 | 允许 | 按遗忘流程可销毁 |
| 密文哈希 `ciphertext_sha256` | 允许 | 只校验存储完整性，不可反推原文 |
| 键控指纹 `content_fingerprint` | 允许（限 Archive 内部） | HMAC 密钥与加密密钥分离；不外发、不跨事件比对、随记录销毁 |
| 明文正文、摘要、关键词、原文 SHA-256 | **禁止** | 任何长期存储位置一律不得 |

> 关键区分：**"不得留原文"不等于"不得留密文"。**
> Archive 的存在意义就是保存加密原始记录；它允许存在的前提是
> ①加密 ②独立密钥 ③Brain 无读取能力 ④有限保留 ⑤不可反向喂给主观记忆。

**输入信任边界（SH-004 修正）**

- 外部只能提交 `soul.stimulus.input.v1`。该信封**不声明** `receivedAt` 且顶层封闭，
  因此适配器提交 `receivedAt` 会被判为 `schema_invalid`，**而不是**被信任、被覆盖或被忽略。
- `receivedAt` 只能由 Ingress 在**受信任接收路径**内生成，是系统唯一权威的接收时间；
  归一化后信封为 `soul.stimulus.v1`，Runtime 只消费这一层。
- `occurredAt` 允许来源自报，属**来源声明**：可缺失、可偏斜、可错误，
  **不得**当作"系统何时知道这件事"的依据。

### 6.2 可测试判据

**明文判据**：向系统注入带唯一标记串的刺激，遍历所有库表、索引、检查点与缓存，
该标记串**不得**出现在：`events` 任意列、`tasks.payload_json`、`runtime_state.checkpoint_json`、
`archive_decisions` 任意列、`archive_conflict_records` 任意列、日志、
**IPC 请求/响应日志、trace 与故障转储**、**错误响应体（`ErrorResponse.error.message`）**、
`archive_records` 的任何**非密文**列。

**密文判据**：同一标记串在 `archive_records.content_enc` 中**不得**以明文形式出现
（即该 BLOB 中搜不到标记串原文）；且用 Brain 身份无法解密该 BLOB。

具体禁止与流转规则见 `RUNTIME-LIFECYCLE.md` §7.1；字段级约束见 `DATA-MODEL.md` §3.1。

## 7. 数据库与 Markdown 的权威关系

- **数据库是权威来源。**
- `SOUL.md` / `IDENTITY.md` / `MEMORY.md` 等 Markdown 是**版本化投影**：
  外部编辑后必须经 Schema、版本、权限校验才能导入。
- **禁止双主写入**：不允许文件和数据库同时作为权威。
- 人格可自行修改的内容（自我叙事、偏好）与永不允许人格修改的系统授权（密钥、授权策略）必须分离存放。

## 9. 明确允许与明确禁止

**允许**

- 主观记忆变形、细节遗失、来源误判、人物混合、时间错置、完整虚假自传体。
- 虚假主观记忆影响模拟情绪与关系。
- 用户提供新现实信息，作为**新观察**影响后续理解（这不叫"恢复记忆"）。
- 管理员按隐私策略清理 Archive（但不得因此改写主观叙述）。

**禁止**

- 用 Archive 作为"隐藏正确答案"去纠正或重建主观记忆。
- 用主观确信度授权任何现实动作。
- 向用户虚构操作结果、聊天证据、财务记录或现实人物的事实。
- **用异常字符串、堆栈、文件路径或输入片段拼装错误响应**：`ErrorResponse.error.message`
  只能取 `packages/contracts` 中 `ERROR_MESSAGES` 的固定文案，Schema 强制 `code` ↔ `message` 配对，
  自由文本会被判为 `schema_invalid`。
- 为通过测试而删除安全约束，或用 Mock 结果冒充真实功能。
- 在梦境中执行真实动作或外发消息。

## 11. 真实遗忘的存储约束

遗忘的事务流程见 `RUNTIME-LIFECYCLE.md` / `DATA-MODEL.md`。本节只规定**哪些存储位置必须被覆盖**，
以及**哪些位置天然会泄露**。

### 11.1 必须清理的位置

| 位置 | 风险 | 必须做的事 |
|---|---|---|
| 主观正文（加密列） | 密钥仍在即可解 | 删除密文 + **销毁对应内容密钥** |
| 片段表 | 同上 | 逐片段删除并销毁密钥 |
| 关系边 | 边端点已删但边仍可推断 | 删除所有以该节点为端点的边 |
| **FTS 索引** | **默认明文**，删了正文仍能搜到 | 见 10.2，必须专门处理 |
| 向量索引 | 向量可反向推断语义 | 删除对应条目并重建分片 |
| 内存缓存 / 激活状态 | 进程内残留 | 失效缓存、清除活跃子图条目 |
| 思维快照 / 检查点 | 可能含被引用内容 | 删除相关线程状态；检查点不得含正文 |
| 梦境输入 | 已删记忆仍可能被梦引用 | 睡眠/梦境任务启动前按 epoch 重校验可见性 |
| 历史修订 | 旧版本行 | 不保留可读历史修订，或修订本身加密 |
| 可读快照 / 导出 | 明文副本 | 导出物必须临时且受控删除 |
| 备份 | 可恢复旧内容 | 只存密文；密钥状态单独受控，不得随备份一起还原 |

### 11.2 FTS 的明文问题（未完全解决，见 OPEN）

SQLite FTS5 索引内容默认是**明文**，`node:sqlite` 无法对索引加密。这意味着"删除正文却保留索引"会直接泄露。

当前决议（P3 前必须定稿）：

- FTS 只索引**允许长期存在**的内容；可遗忘内容**不得**进入常驻 FTS。
- 可遗忘内容的检索走"**临时重建**"：按需从解密后的正文构建内存索引，用完即弃。
- 或改为只索引**主题标签 / 概念 ID**，不索引原文片段。

> 这是一条 **OPEN** 项：需要 P3 做基准测试后定案。在定案前，不得实现"常驻明文 FTS + 可遗忘内容"的组合。

### 11.3 WAL 与 secure_delete

- 删除行不等于从磁盘抹除。必须开启 `PRAGMA secure_delete = ON`，或对敏感内容永远只存密文。
- WAL 会保留旧页：遗忘事务完成后必须执行 `PRAGMA wal_checkpoint(TRUNCATE)`。（目标约束，尚未实现为应用层显式语句。`DatabaseSync.close()` 可能触发 SQLite 默认自动 checkpoint，不能代替本条。）
- 删除后必须做一次物理验证：在库文件与 `-wal` 中搜索金丝雀，命中数必须为 0。

### 11.4 备份

- 备份只保存**密文**与必要的元数据；内容密钥的状态独立管理，**不得**与备份放在一起。
- 恢复时若某批次的密钥已被销毁，则该批内容恢复后**不可解密**，且不得因此回退墓碑或 epoch。
- 恢复后必须跑一次金丝雀检查：已遗忘内容不得因恢复而重新出现。
